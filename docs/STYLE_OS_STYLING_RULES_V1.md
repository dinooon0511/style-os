# STYLE OS — Styling Rules & Algorithm v1.0
Дата: 23.10.2026. Статус: первая рабочая гипотеза, необходима калибровка на оценках владельца.
Основа: 35 положительных пользовательских референсов (первые 15 + 20 + 15; фактически 50 фотографий за всю переписку; предыдущие разборы выделили 7 блоков в последних 35), наблюдения из переписки и обобщённые принципы композиции мужского гардероба. Референсы не дают оснований считать отсутствие какого-либо фасона ошибкой.

## 1. Семь стилевых направлений
| ID | Направление | Устойчивые признаки | Исключения |
|---|---|---|---|
| minimal | Contemporary minimal | нейтральная палитра, чистые линии, трикотаж + широкие брюки, минимум рисунка | допустим узкий верх и свободный верх |
| summer_relaxed | Summer relaxed | лёгкие ткани, свободные рубашки, открытый ворот, простая обувь | летний комплект может быть тёмным |
| classic | Classic / preppy | рубашка, поло, трикотаж, аккуратная обувь, спокойная гамма | современная классика допускает широкие брюки |
| utility | Workwear | плотный хлопок, деним, кожа, землистые оттенки, практичный верх | не обязателен тотал-utility |
| dark_minimal | Dark minimal | чёрный/графит/темно-синий, интересный силуэт и разные фактуры | близкие оттенки могут сочетаться без полного совпадения |
| soft_tailoring | Modern formal | широкие костюмные брюки, галстук вне костюма, трикотаж и короткая куртка | смешение формальности специально допустимо |
| winter_layered | Winter layered | тёплые слои, объём верхней одежды, кожа/шерсть/деним, плотная обувь | длинное пальто не требует узкого низа |

Эти направления — теги эстетики. Сезонность отдельно от стиля: winter_layered и summer_relaxed позднее следует хранить как контекстные режимы, допускающие сочетание с minimal/classic/utility.

## 2. Правила подбора (положительные, контекстные)
| Правило | Условие | Эффект | Основание |
|---|---|---|---|
| C01 | 2–4 нейтральных или согласованных приглушённых цвета | бонус к цветовому баллу | повторяется во всех блоках |
| C02 | принадлежность близкой тональной/землистой группе | бонус | neutral, olive, brown, navy |
| C03 | монохром с разными фактурами | бонус, а не штраф «слишком мало цветов» | dark minimal |
| P01 | широкий низ + компактный, заправленный или короткий верх | бонус | несколько десятков референсов |
| P02 | свободный верх + широкий низ | НЕ запрещать; оценивать по контексту streetwear/relaxed | oversized примеры |
| P03 | короткая структурная куртка + широкие брюки | бонус | leather/utility/winter |
| F01 | кожаная обувь + костюмные брюки | бонус формальности | classic/soft tailoring |
| F02 | кроссовки + свободный деним/карго | бонус casual | streetwear |
| F03 | галстук + кардиган или короткая куртка | разрешённый приём | modern formal |
| L01 | рубашка + джемпер/кардиган | бонус многослойности | classic/winter |
| L02 | виден узкий белый нижний слой | умеренный бонус, не обязательное требование | minimal/streetwear |
| M01 | текстурный верх + гладкие брюки | бонус фактурного контраста | свитеры и брюки |
| M02 | деним + кожа или плотный хлопок | бонус при utility | workwear |
| W01 | жара + плотное пальто/худи | штраф температурной уместности | проектное ограничение, не вкусовая оценка |
| W02 | холод + нет утепляющего слоя | предупреждение и штраф | проектное ограничение |
| D01 | несколько почти одинаковых образов в выдаче | понижать повтор | продуктовая гипотеза |
| R01 | отсутствует вещь | показывать как «докупить», не выдавать за имеющуюся | требование продукта |

## 3. Параметры вещи — обязательный контракт
item_id, category, type, subtype, fit, leg_shape, rise, length, color_family, color_tone, material_family, texture, weight, formality (0..4), warmth (0..4), silhouette_volume, neckline, sleeve_length, layering_role, style_tags, weather_tags, shoe_profile, image_url, source, verified, sku, product_url.
Типы с невозможными свойствами допускают null. Теги не заменяют реальные характеристики.
Сейчас в index.html доступны лишь type, color, fit, season и иногда material. Остальные поля нужно заполнять постепенно, а не выводить как подтверждённые из отсутствующих данных.

## 4. Последовательность движка
1. Получить гардероб и контекст (повод, погода, выбранный стиль).
2. Построить несколько кандидатов: верх + низ + обувь, по необходимости внешний слой.
3. Жёстко проверить невозможные комбинации категорий и сильную температурную несовместимость.
4. Оценить C (цвет), P (силуэт), F (формальность), L (слои), M (фактуры) и U (пользовательские предпочтения).
5. Собрать список `fired_rules` c ID и короткими объяснениями.
6. Присвоить балл в диапазоне 0–100; штрафовать отсутствующие позиции отдельно от эстетики.
7. Убрать дубли по ID вещей и очень близкому составу.
8. Вернуть 3–5 вариантов; при неполном гардеробе показать недостающие вещи.
9. Собирать like/dislike с причиной и менять только мягкие веса, не жёсткие ограничения.

## 5. Параметры формулы
Предварительная будущая формула: score = 0.25 Color + 0.25 Proportion + 0.20 Formality + 0.15 Layer/Texture + 0.15 Preference.
В действующем MVP использованы целочисленные бонусы/штрафы с оценкой 0–100, а не эти веса: такое упрощение временное. Нельзя интерпретировать 91/100 как процент объективной стильности.

## 6. Набор тестов калибровки
T01 тёмный минимализм с широкими брюками + компактный верх: должен быть положительный кандидат.
T02 wide jeans + oversized hoodie + sneakers: допустимо в streetwear, не банить за «двойной объём».
T03 warm-weather lightweight shirt + relaxed trousers: положительно, включая тёмную палитру.
T04 collar shirt + tie + cardigan + wide trousers: допустимо.
T05 heavy shearling/puffer + wide trousers: допустимо в холод.
T06 coat + shorts in hot weather: штраф погодной применимости.
T07 2 identical combinations differing only by single equivalent catalog SKU: понизить повтор.
T08 same outfit without owned shoes: показать «докупить», не скрывать недостаток.
T09 all black with different fabrics: не штрафовать за монохром.
T10 3+ conflicting brightly saturated colors: осторожный штраф, НЕ запрет (требует негативных примеров).

## 7. Неподтверждённое и следующие итерации
- 35 положительных примеров не формируют негативную выборку. «Ошибка» требует негативных примеров и причин оценки.
- Нельзя автоматически определять рост, фигуру, реальный состав ткани или посадку по одному каталожному названию.
- Не переносить описанные в референсах вкусы в жёсткие запреты для всех пользователей.
- Для проверки нужны 30–50 новых образов, которые владелец оценит 1–5, и 10–20 намеренно неудачных сочетаний с причинами.
- Внедрение v1: STYLE_RULES, STYLE_PALETTES, itemTags, compatibility и generateLooks в index.html. Расширение тегов, весов и персонального feedback — следующий релиз.
