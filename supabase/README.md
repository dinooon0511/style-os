# STYLE OS — подключение Supabase (только test)

## Обязательное действие владельца проекта
1. Открой Supabase Dashboard проекта `maqhxkhltckttfwhyoqn` → **SQL Editor**.
2. Выполни SQL из `supabase/migrations/20261027_user_state.sql`. Без этого база не готова, а приложение не сможет сохранять пользователей.
3. В **Authentication → Providers → Email** включи Email, регистрацию паролем и **Confirm email**.
4. В **Authentication → URL Configuration** укажи **Site URL**: `https://dinooon0511.github.io/style-os/`; в **Redirect URLs** добавь `https://dinooon0511.github.io/style-os/**` (и точный URL страницы).
5. Настрой отправку писем через SMTP перед публичным запуском; встроенная отправка Supabase ограничена и не предназначена для массовой регистрации.
6. Включи в Authentication меры защиты от автоматизированных регистраций, в том числе CAPTCHA (потребуется настроить ключ на клиенте), и выбери требования к паролю.
7. Проверь RLS: пользователь A не должен читать, обновлять или удалять строки пользователя B. Не отключай RLS и не публикуй secret/service-role key.

## Архитектура
- `auth.users`: учётные записи управляются Supabase Auth; пароль никогда не сохраняется в приложении.
- `public.user_state`: отдельная JSONB-строка на каждого пользователя с RLS-политиками `auth.uid() = user_id`.
- Данные синхронизируются после изменений с задержкой около 650 мс.
- Старые записи в `localStorage` предлагается импортировать **только при первом создании облачной записи**, после подтверждения пользователем.
- Publishable key открыт в клиентском коде по назначению; секретных ключей там нет.
- Нельзя считать систему готовой для реальных пользователей до проверки SMTP, безопасной конфигурации Auth, RLS и тестов в браузере.

## Контрольные сценарии
1. Регистрация и email confirmation.
2. Вход, выход, восстановление пароля.
3. Создать и сохранить вещи, перезагрузить приложение — данные восстановятся.
4. Создать два аккаунта, проверить изоляцию гардеробов.
5. В режиме Offline проверить уведомление об ошибке облачного сохранения.
6. При повторном входе убедиться, что чужой локальный гардероб не импортируется автоматически.
